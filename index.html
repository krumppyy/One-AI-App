How to use this app

with AI tutor

1 · New here? Do this first (2 minutes)

  1. Open AI Chat and ask anything — this checks you are online and shows how answers stream.
  2. Open Image, type a red fox in snow, cinematic light, hit Generate image.
  3. Press → Video under the result, add the fox lifts its head and looks around, hit Generate video.
  4. Stuck anywhere? Hit ? bottom-right and ask in plain words.

2 · AI Chat

  • Pick a model, type, Enter sends (Shift+Enter = new line).
  • Select any reply text → popup sends it to Image / Video / Voice.
  • Chats save on this device; search them from the left list.

3 · Image Studio

  • Text mode draws from words; Edit mode repaints your uploaded picture.
  • Short prompt + Auto-enhance beats a long prompt you write by hand.
  • Result bar: Color grade → Upscale → Format → Download.

4 · Video Studio (the main event)

  1. Drop a starter image (or video frame via scrub + Use this frame).
  2. Describe the motion: who moves, how, and the camera (slow push-in).
  3. Pick Auto model first. Manual pick only if Auto stalls.
  4. Keep the Run log on Simple unless debugging.
  5. Nothing free available? The on-device rig still renders a camera move.

5 · Reader → Voiceover

  • Reader: drop PDF / DOCX / photo of text → text extracts on-device → Generate narration → Send to Voice.
  • Voiceover: paste script, pick voice, Speak, export WAV / MP3 / OGG below. 🎤 Dictate types by voice.

6 · Storyboard Studio

  • Type a story idea, set scene count, hit 📖 Build story — AI splits it into scenes.
  • Hit Generate storyboard for all frames, or + 1 frame for one. Click a card to preview, drag to reorder.
  • Switch stories with the Project dropdown (+ New / Delete) — everything auto-saves.
  • ▶ Compile + save turns frames into video (WEBM/MP4/MOV/MKV/GIF) and saves it to the Library.
  • 🎙 Voiceover sends one narration line per scene to the Voice tab; ✨ Narrate rewrites scenes into spoken narration first.

7 · Editor

  • ⬇ Studios pulls your latest Video + Image results into the bin.
  • Double-click a bin item = add to V1. Drag = move, edges = trim, S = split, Space = play.
  • Export video renders on this machine — keep the tab visible.

8 · Settings & privacy (read once)

  • Where the rendering happens: your own GPU server first (free Colab), free pool next, this device last.
  • The free pool is metered per address — address rotation is what keeps it going.
  • Library is encrypted on-device covers this browser's storage, not third-party servers.

9 · Feedback & Library

  • 💬 Feedback (top-right): pick a category, write it, Send — top-voted items get built first.
  • Library (topbar): every finished clip / image / story / narration, saved on this device. Search, filter, tap to reuse.

Settings

Where the rendering happens free & unlimited

Bring your own GPU and the app stops depending on anyone else. Run the included server on a free Google Colab T4 (or any machine with an NVIDIA / Apple GPU), then paste its address here — the models download once and then work offline too. No account, no token, no Hugging Face.

Checking compute options…

Weights download once and then work offline. The 14B models render at their native 720p whatever quality you pick — that is the resolution they were trained at, and it is the difference between a clean clip and a mushy one.

Free GPU boost optional

These are public Hugging Face Spaces. Hugging Face meters them per day: about 2 minutes of GPU time per address if you are not signed in, and 5 minutes per account on a free account. A token is therefore optional — it raises the ceiling a little and moves you up the queue. If you run into "the pool refused this job", the fix that actually works is the address rotation below, or your own server above.

No key is built into the app — everyone pastes their own, and it never leaves their browser except to Hugging Face with their own jobs.

NSFW first frame free

A video model animates the frame you give it — it will not undress anyone by itself. So with NSFW mode on, the app makes the first frame explicit before rendering. Auto draws a fresh explicit frame from your prompt with Pollinations — seconds, no key, no quota, always answers — and the video model animates that frame. It is a reliable result of a new person, not an edit of your photo. Undress my image repaints your own picture with AI Horde's free, uncensored inpainting, and it works out which pixels are clothing first with a 4 MB clothes-detection model that ships inside this generator and runs in your browser — the picture never leaves your machine for that step. Only the clothing it finds is regenerated and your original is laid back over everything else, so the face, hair, pose and background stay yours at the photo's own resolution. “Repaint area” chooses what counts as clothing, or drag a box if you would rather pick the region yourself. Its workers run their own safety filters, so several attempts are made at once and the first clean one wins; only a handful of AI Horde's workers accept inpainting, so the queue can be long — a free aihorde.net key skips almost all of it.

Paid model APIs bring your own key

Kling, MiniMax / Hailuo and Runway are commercial services — there is no free tier. Add a key to unlock them; you are billed by that provider, not by us. Nothing is pre-filled: each visitor uses only their own key, stored on their own device.

MuAPI paid · one key, 51 models

MuAPI is a single key in front of the commercial video models — Kling, Veo, Sora, Seedance, Wan, Hailuo, Vidu, LTX, PixVerse and their unfiltered variants. There is no free tier: the key costs nothing to create, generations are paid for with credits on that account. The model list is split into six sections — ◆ flagship, ◇ balanced, ⚡ fast, ▾ budget, ✦ uncensored and ✎ text→video — and the note under the picker names the section the selected model came from. Two things are worth knowing first. MuAPI sends no CORS headers, so every request is relayed through Perchance's own fetch proxy. And it accepts reference images by public URL only — a data URL is rejected — so the frame being animated is published to the upload host before each segment is submitted. Pick a model and press Quote the selected model to see the exact price of the run you have set up — that quote comes free from MuAPI's own billing maths and needs no key.

Custom Gradio space

Any public Hugging Face Gradio video space works. Paste its URL — the endpoints are auto-detected.

Privacy & IP rotation free

A relay is any URL that fetches on your behalf, so the model only ever sees the relay's address instead of yours. Your own AIVideoGen server already serves one at /api/relay, a Cloudflare Worker you deploy in one click works just as well, and Perchance's own proxy is built in — nothing to install. Only add relays you trust: a relay sees the request headers, and if you paste a Hugging Face token that token travels with the request (it identifies your account to the model owner, never your address).

The free public pool also counts each free GPU allowance per address, so when a model refuses a job, asking again from somewhere else is usually all it takes. A different address brings its own allowance; a shared fallback (Perchance's proxy) has already been spent by everybody else, which is why it is only ever tried after a refusal.

No relays yet — add one, or just keep using your own connection.

The app cannot switch your VPN or proxy itself — that lives outside the page. What it can do: rotate relay paths per generation, refuse to leak direct, and prove each path below.
Diagnostics idle — press Check addresses or Probe Perchance hooks.

Run the renderer on your own GPU

Option A — free Google Colab (T4 GPU)

  1. Download the notebook (or open src/colab/AIVideoGen_Colab.ipynb from the editor's file panel).
  2. In Colab: File → Upload notebook, and sign in with your Google account.
  3. Runtime → Change runtime type → T4 GPU, then Runtime → Run all.
  4. The last cells print a public https://…trycloudflare.com address — paste it below and press Test.

Colab is free but the session ends after a while of inactivity, and the address changes each time — just re-run the last cell and paste the new address. The model's weights are fetched from ModelScope on first use (90–127 GB for the 14B models, ~35 GB for wan5b, which is what fits a free Colab) and the notebook offers to cache them in your Google Drive so a restart doesn't fetch them again.

Option B — your own machine

Install Python 3.10+, then in the project's src/server folder: 

pip install -r requirements.txt
python server.py                      # NVIDIA / CPU
python server.py --tunnel cloudflare  # + a public URL, no account
python server.py --model wan5b --preload
python server.py --list               # the model catalogue
python server.py --download wan5b     # fetch the weights now, then exit
python server.py --weights            # what is already on disk

CUDA builds of PyTorch: pip install torch --index-url https://download.pytorch.org/whl/cu124. On Apple silicon it runs on MPS automatically. Weights come from ModelScope first (its copy of the Wan family is complete and it is usually much faster than huggingface.co), then Hugging Face, then the mirror you name with --hf-endpoint https://hf-mirror.com. They are kept on disk, so once a model has been used the whole thing works with the internet unplugged — and Download next to a model in the settings list fetches one up front, with a progress bar.

Other free GPU hosts

The same server.py runs unchanged on Kaggle (≈30 GPU-h/week, enable GPU + Internet in the notebook settings), Amazon SageMaker Studio Lab (free account, persistent storage), Lightning AI Studio (free monthly GPU credits) and Modal / RunPod free tiers. Start it exactly as in Option B — the tunnel flag gives you a shareable address on all of them.

Nothing at all?

Set the compute mode to Only this device. The built-in offline camera rig turns any picture into a moving clip on your phone or laptop with no internet, no GPU and no download — it just can't invent new detail the way a diffusion model can.

Change the address your requests come from

What this actually does

Every generation is one POST to a model. That request decides which free GPU allowance gets spent, and it is the request that carries your address. Send it through a relay and the model sees the relay instead — and a different address brings its own allowance.

The numbers, straight from Hugging Face's own documentation: the shared free GPU pool gives 2 minutes a day per address if you are not signed in, and 5 minutes a day per account on a free account (40 minutes on PRO). The allowance resets 24 hours after your first GPU use, and it is counted in seconds of GPU time — so a 2-second, 5-second and 10-second clip cost very different amounts of it. Rotating addresses is what turns "2 minutes" into "2 minutes per address", which is the only honest way to make the free pool keep going.

When a refusal happens, the retry also drops your token: without it the allowance is charged to the new address instead of to your (already spent) account.

Keeping models from seeing your address (the first switch above, on by default) goes further than rotation: while it is on, nothing about the run leaves from your connection at all. Every request a model could ever see — the parameter list, the reference-frame upload, the job itself, the stream that reports its progress, and the finished clip's download — travels through a relay, and the X-IP-Token that decides which free allowance is spent is never sent alongside the stream. If no relay can carry a request, the run stops and says so rather than quietly falling back to your address.

What a model owner can still see: the prompt, the reference image, and — if you pasted a Hugging Face token — that token, which names your account. The relay itself can see the request, so only add ones you trust, and the site serving this page can see that you pressed Generate. Nothing here can hide the prompt's content from the model, because the model has to read it to do the work.

Starting every run fresh, and leaving no trace

Start every run fresh (on by default) drops every bench record before a run and, when there is more than one address, steps to the next one first. This is what lets a second run happen at all: the allowance is counted per address and shared by every free model, so a model that just refused is not really "broken" — it is out of allowance on that address and fine on the next. If a model does refuse mid-run for allowance reasons, the app asks the same model again from the next address before moving on.

Wipe traces after every run (also on) expires every cookie this page's origin can see, clears web storage, every cache bucket, the browser's resource-timing rows (the list of URLs it contacted) and the quota records the run wrote. Your clip library and settings live in this browser's own IndexedDB and are deliberately kept.

What it cannot do: delete a cookie that another origin set — huggingface.co's cookies belong to huggingface.co and no page here may touch them. That is why every request the app makes is sent with credentials: "omit" and no referrer: no cookie is ever sent to a model, and none is created because of a run in the first place.

Reset (the button in the Studio header) is the same wipe on demand, plus the two things a single wipe cannot do: it forgets the router's record of which routes refused, and it steps to a different address. It can also clear the studio controls, and — if you ask it to — the saved library. A run that the whole pool blocks triggers the same reset by itself (Settings → Reset automatically when a run is blocked), so pressing Generate again starts from a clean browser and a fresh address rather than from the wall the last run hit.

Option A — a one-click Cloudflare Worker recommended

  1. Sign in (free) at dash.cloudflare.com.
  2. Workers & Pages → Create → Worker, give it any name, Deploy.
  3. Edit code, delete everything, paste the code below, Deploy.
  4. Copy the https://…workers.dev address it gives you.
  5. Paste it into My relays above, set the rotation to Rotate after every generation, and press Check addresses — it should answer with an address that isn't yours.

The free plan allows 100,000 requests a day, so it will never be the thing that runs out.

Option C — a VPN for the whole browser install needed

        

          A web page cannot switch on a VPN — only your device can. If you want everything on this
          machine to change address, these are free, open source and take a minute:
        

        
    
          
  • Cloudflare WARP (1.1.1.1) — free, no account, one toggle, works on phones and desktops.
    • 
          
  • Proton VPN Free — open-source clients, free servers, no data cap (speed limited).
    • 
          
  • WireGuard — the open-source tunnel itself, if you have a free config from anywhere.
    • 
          
  • Tor Browser — strongest untracing, much slower; fine for the browser, not for big uploads.
    • 
        

        

          Honest note: with a VPN, changing server means disconnecting and reconnecting, so the rotation above
          still does the job better for this app — and it needs nothing installed.

  1. Rotation spreads the free pool's per-address allowance over as many addresses as you can add — a Cloudflare Worker, each of your GPU servers, and one worker per account if you have more than one.
    2. 
          
  2. Your own GPU server has no quota at all, no per-run cost and no third party. This is the real answer, and it is already built: Settings → Where the rendering happens.
    3. 
          
  3. The on-device renderer works with the internet unplugged, forever, for free.
    4. 
        

        

          The app always walks that ladder instead of erroring out, so a run always produces something.

        address — the fastest way out of “the pool refused everything”. The free allowance is metered per
        address, so a clean browser plus a new address is a new allowance. Your API keys and
        your settings are never touched.
